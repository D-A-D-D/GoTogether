Landing on `/login` after logging out from a protected page is arguably fine UX either way, so left as-is; worth a real fix (e.g. have `useRequireAuth` skip its redirect during an intentional logout) if it ever produces a worse outcome than "two reasonable pages, nondeterministic pick." *2026-09-30*

- **[note]** — Process lesson, not a product gap: an already-registered service worker from earlier testing in this session caused a genuine (if confusing) crash — a stale cached JS chunk missing a function that had since been added — on a fresh page load, twice, in this chat-testing pass. Clearing SW registrations + Cache Storage (`navigator.serviceWorker.getRegistrations()` + `caches.keys()`, unregister/delete each) is now something to do *before* starting any live verification in this tool, not just when something looks broken — the same fix already happened once during the PWA polish pass and cost real time being rediscovered here. *2026-09-30*
