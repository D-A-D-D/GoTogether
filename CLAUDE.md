# Working agreement for this project

GoTogether is tracked across three living docs — keep them current, don't let them drift:

- **docs/ROADMAP.md** — checklist of implemented vs. pending work, by phase, plus a table of open decisions. When you finish a task from it, check it off and move it under "Implemented" with a one-line note of what landed. When scope changes, edit the checklist, don't leave it stale.
- **docs/IDEAS.md** — backlog of ideas raised in conversation but not yet built. When a new good idea comes up (yours or the user's) that isn't already scoped into the roadmap, log it here rather than losing it. When one gets picked up, move it into ROADMAP.md under the right phase and mark the IDEAS.md entry `→ scheduled`.
- **docs/BLUEPRINT.md** — the architecture/product plan itself. It's a set of defaults, not settled law — if an implementation detail changes materially from what's written (a different matching weight, a schema change, a reversed open decision), update this file in the same pass, not as an afterthought.

Read docs/ROADMAP.md before starting new work to see what's already done and what's next in the current phase.
